# my_first_bot

Telegram-бот технической поддержки на базе LLM (через OpenRouter). Отвечает на вопросы пользователей в роли специалиста поддержки, а на сообщение-оповещение о сбое создаёт сервисную заявку и сообщает о ней в чат.

Стек: Python 3.12, `uv`, aiogram 3 (long polling), пакет `openai` + OpenRouter, Make, Docker, хостинг Railway. Подробнее: [`docs/vision.md`](docs/vision.md).

## Быстрый старт

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен. Ключ OpenRouter берётся на [openrouter.ai/keys](https://openrouter.ai/keys).
2. Скопируйте `.env.example` в `.env` и заполните значения:

   | Переменная | Обязательна | Описание |
   |---|---|---|
   | `TELEGRAM_TOKEN` | да | токен бота от BotFather |
   | `OPENROUTER_API_KEY` | да | ключ OpenRouter |
   | `MODEL_NAME` | нет | модель, по умолчанию `openai/gpt-4o-mini` |
   | `LOG_LEVEL` | нет | уровень логов, по умолчанию `INFO` |
   | `ALERT_PATTERN` | нет | ключевое слово или регулярное выражение оповещения, по умолчанию `#alert` |
   | `ALERT_CHAT_ID` | нет | принимать оповещения только из этого чата или канала |
   | `ALERT_SENDER_ID` | нет | принимать оповещения только от этого отправителя |
   | `NOTIFY_CHAT_ID` | нет | куда отправлять уведомления о заявках; по умолчанию — чат оповещения |

   Файл `.env` не попадает в git и в Docker-образ. Не публикуйте токен и ключ.

3. Запустите одним из способов (нужны [uv](https://docs.astral.sh/uv/) и Make; для Docker ещё Docker Desktop):

   ```
   # локально
   make install
   make run

   # в Docker
   make docker-build
   make docker-run
   ```

   Одновременно запускайте только один экземпляр бота: два процесса с одним токеном конфликтуют (ошибка `Conflict: terminated by other getUpdates request`). Если бот работает в Railway, локально его не запускайте.

Остановка: `Ctrl+C`. Другие цели Make: `venv`, `clean`.

## Деплой в Railway

1. В [Railway](https://railway.com) создайте проект: New Project → Deploy from GitHub repo → этот репозиторий.
2. Railway соберёт образ по `Dockerfile`; настройки сборки и перезапуска лежат в `railway.json` (перезапуск при падении).
3. В сервисе откройте Variables и задайте `TELEGRAM_TOKEN`, `OPENROUTER_API_KEY` и при необходимости остальные переменные из таблицы выше.
4. Оставьте один экземпляр сервиса. Публичный домен не нужен: бот сам опрашивает Telegram (long polling).
5. Каждый push в `main` запускает новый деплой. Логи — в Deployments → View Logs; после старта там появляется `Bot started alerts_enabled=True`.

История диалогов и заявки-заглушки хранятся в памяти и пропадают при каждом редеплое и перезапуске.

## Как пользоваться

- `/start` — приветствие.
- Любой текст — ответ специалиста поддержки. Бот помнит последние 20 сообщений чата.
- Сообщение, подходящее под правило оповещения (по умолчанию содержит `#alert`), — бот создаёт заявку и пишет «Заявка №N создана: тема» с кратким описанием. Тему и описание формулирует модель; если она недоступна, берётся текст оповещения.
- Повторная обработка того же сообщения не создаёт вторую заявку.
- Стикеры, фото и другие нетекстовые сообщения — бот просит написать текстом.
- Сообщение длиннее 2000 символов — вежливый отказ.
- При сбое модели пользователь получает короткое понятное сообщение, бот продолжает работать.

### Оповещения от других ботов

В группах Telegram не доставляет боту сообщения других ботов. Если оповещения шлёт бот мониторинга, публикуйте их в канал и добавьте туда нашего бота администратором: посты канала бот получает от любого автора. В канале бот не ведёт диалог, а только обрабатывает оповещения.

## Настройка

- Роль и стиль бота: `SYSTEM_PROMPT` в `src/my_first_bot/config.py`; оформление заявки — `TICKET_PROMPT` там же.
- Правило оповещения: переменные `ALERT_*`, логика — `src/my_first_bot/alert_handler.py`.
- Система заявок: интерфейс `TicketService` в `src/my_first_bot/ticket_service.py`. Сейчас подключена заглушка `StubTicketService`; для реальной системы нужен новый класс с тем же интерфейсом и замена в `runner.py`.
- Уведомление о закрытии заявки: `TelegramBot.close_ticket` — будет вызываться, когда появится источник события закрытия.
- Размер истории (`MAX_HISTORY`) и лимит ввода (`MAX_INPUT_CHARS`): `src/my_first_bot/telegram_bot.py`.
- Лимит длины ответа (`MAX_TOKENS`): `src/my_first_bot/llm_client.py`.

## Ограничения

- Заявки создаются в заглушке и не попадают во внешнюю систему.
- Закрытие заявки пока не запускается из Telegram.
- История и заявки хранятся только в памяти.
- Нет базы данных, webhook, автотестов и CI.
